API de faturamento para franqueados

Puxe o faturamento da sua unidade para o seu próprio dashboard: Power BI, Google Sheets, Metabase ou um sistema seu. A API é só de consulta: nenhuma chamada altera dados na Bliq.

URL base https://app.bliqbrasil.com.br/api/v1

Primeiros passos

  1. Entre no painel Bliq com o usuário dono da franquia e abra app.bliqbrasil.com.br/franqueado/api. A tela não aparece no menu: o acesso é por este endereço.
  2. Clique em Nova chave, dê um nome que identifique a integração (ex.: “Power BI do escritório”) e escolha a validade.
  3. Copie a chave na hora. Ela aparece uma única vez; a Bliq não guarda uma cópia.
  4. Faça a primeira chamada:
curl https://app.bliqbrasil.com.br/api/v1/faturamento/resumo \
  -H "Authorization: Bearer SUA_CHAVE"

Sem parâmetros, a resposta traz o mês corrente até agora. Os números batem com a tela Relatório do painel.

Autenticação

Toda chamada leva a chave no cabeçalho Authorization, no formato Bearer <chave>. A chave é um JWT assinado pela Bliq que identifica a sua unidade e dá permissão apenas de leitura.

  • Uma chave vale para uma unidade. Quem tem várias unidades cria uma chave em cada uma (troque a unidade no painel antes de criar).
  • Crie uma chave por integração. Se uma vazar, você revoga só ela e as outras continuam funcionando.
  • Revogar é imediato. Em /franqueado/api, o ícone de lixeira desativa a chave na hora.
  • Validade: 30, 90, 180 dias, 1 ano ou sem expiração. Depois de expirada, crie outra.
  • A tela mostra quando cada chave foi usada pela última vez (atualizado a cada 5 minutos).
Guarde a chave no servidor. Ela dá acesso a todo o faturamento da unidade. Não coloque em código que roda no navegador nem em planilha compartilhada com terceiros. Chamadas feitas direto do navegador de outro site são bloqueadas (CORS).

Regras e limites

60consultas por minuto, por chave
366 diasperíodo máximo por consulta (31 com agrupamento por hora)
500vendas por página, no máximo

O que conta como venda

Mesmo critério da receita do Relatório do painel: ciclo finalizado, com pagamento aprovado e valor maior que zero. Ciclos manuais de brinde e manutenção não são venda; aparecem só como contagem em cortesias. Uma venda entra na API quando o ciclo termina, não quando o cliente paga.

Datas e fuso horário

  • Os parâmetros de e ate aceitam AAAA-MM-DD, lido no horário de Brasília. ate=2026-10-17 inclui o dia 17 inteiro.
  • Também aceitam data e hora ISO 8601 completa, como 2026-10-17T14:00:00-03:00.
  • Sem de, a consulta começa no dia 1 do mês de ate. Sem ate, vai até agora.
  • O período é filtrado pela hora em que o ciclo foi criado no totem.
  • As datas nas respostas vêm em UTC (ISO 8601 com Z). Os rótulos da série (rotulo) já vêm no horário de Brasília.

Valores

Valores em reais, como número com até duas casas decimais (1234.5 = R$ 1.234,50). O ticket médio é receita dividida pelo número de vendas.

Dados de clientes

Por causa da LGPD, a API não devolve CPF, nome, telefone ou e-mail de clientes. Quando o cliente se identifica com CPF no totem, a venda traz um código anônimo dele em clienteId, para você acompanhar recorrência sem receber dado pessoal.

  • O código é fixo: a mesma pessoa tem sempre o mesmo clienteId na sua unidade, inclusive nas vendas antigas.
  • Cada unidade tem códigos próprios. A mesma pessoa aparece com códigos diferentes em unidades diferentes.
  • O código não permite chegar ao CPF nem a qualquer outro dado da pessoa.
  • Venda sem identificação vem com clienteId: null e clienteIdentificado: false. O código depende do CPF digitado no totem; o pagamento sozinho (PIX ou cartão) não identifica o cliente.
GET/faturamento/resumo

Resumo do faturamento

Totais do período: receita, número de vendas e ticket médio, quebrados por forma de pagamento, box e produto. Use para os cartões principais do dashboard.

dedataInício do período. Padrão: dia 1 do mês.
atedataFim do período. Padrão: agora.

GET/faturamento/serie

Série temporal

Receita e vendas agrupadas por hora, dia ou mês, já no horário de Brasília. Períodos sem venda vêm com zero, então dá para ligar direto num gráfico de linha ou de barras.

ParâmetroTipoDescrição
agrupamentohora | dia | mesTamanho de cada ponto. Padrão: dia. Por hora, o período máximo é de 31 dias.
de, atedataComo no resumo.
boxIdtextoFiltra um box.

Exemplo: ?de=2026-10-01&ate=2026-10-03

Exemplos de código

Troque SUA_CHAVE pela chave criada no painel.

import requests

BASE = "https://app.bliqbrasil.com.br/api/v1"
HEADERS = {"Authorization": "Bearer SUA_CHAVE"}

# Resumo do mês corrente
resumo = requests.get(f"{BASE}/faturamento/resumo", headers=HEADERS, timeout=30).json()
print(resumo["receita"], resumo["vendas"], resumo["ticketMedio"])

# Todas as vendas de setembro, página por página
vendas, pagina = [], 1
while True:
    r = requests.get(f"{BASE}/vendas", headers=HEADERS, timeout=30, params={
        "de": "2026-09-01", "ate": "2026-09-30", "pagina": pagina, "porPagina": 500,
    })
    r.raise_for_status()
    dados = r.json()
    vendas += dados["vendas"]
    if pagina >= dados["totalPaginas"]:
        break
    pagina += 1
// Node 18+ (fetch nativo). Rode no servidor, nunca no navegador.
const BASE = 'https://app.bliqbrasil.com.br/api/v1'
const headers = { Authorization: `Bearer ${process.env.BLIQ_API_KEY}` }

const res = await fetch(`${BASE}/faturamento/serie?agrupamento=dia&de=2026-10-01`, { headers })
if (!res.ok) throw new Error((await res.json()).error)
const { serie } = await res.json()

for (const dia of serie) {
  console.log(dia.rotulo, dia.vendas, dia.receita)
}
// Power BI Desktop: Obter dados > Consulta nula > Editor avançado.

// Google Sheets: Extensões > Apps Script. Guarde a chave em
// Configurações do projeto > Propriedades do script, com o nome BLIQ_API_KEY.
// Agende atualizarFaturamento em Acionadores para rodar todo dia.
function atualizarFaturamento() {
  const chave = PropertiesService.getScriptProperties().getProperty('BLIQ_API_KEY')
  const url = 'https://app.bliqbrasil.com.br/api/v1/faturamento/serie?agrupamento=dia&de=2026-01-01'
  const res = UrlFetchApp.fetch(url, { headers: { Authorization: 'Bearer ' + chave } })
  const { serie } = JSON.parse(res.getContentText())

  const aba = SpreadsheetApp.getActive().getSheetByName('Faturamento')
  aba.clearContents()
  aba.appendRow(['Dia', 'Vendas', 'Receita', 'Ticket médio'])
  serie.forEach(d => aba.appendRow([d.rotulo, d.vendas, d.receita, d.ticketMedio]))
}

Erros

Erros respondem com o código HTTP adequado e um JSON com a explicação em error:

{ "error": "Período máximo de 366 dias por consulta" }
CódigoQuando aconteceO que fazer
400Parâmetro inválido: data mal formatada, de depois de ate, período longo demais.Corrija o parâmetro indicado na mensagem.
401Chave ausente, inválida, expirada ou revogada.Confira o cabeçalho Authorization ou crie uma chave nova no painel.
403Franquia bloqueada.Fale com a franqueadora.
404boxId que não pertence à sua unidade.Pegue os ids em /franquia.
429Mais de 60 consultas no mesmo minuto com a mesma chave.Espere os segundos indicados no cabeçalho retry-after.
500Falha do lado da Bliq.Tente de novo em alguns minutos. Se persistir, avise o suporte.

Toda resposta traz x-ratelimit-limit e x-ratelimit-remaining para você acompanhar o consumo do minuto.
